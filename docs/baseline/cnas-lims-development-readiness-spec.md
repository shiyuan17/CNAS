## 1. 规格组合规则

本文件不重复 129 条 P0 的原子描述，而是补齐其共同缺失的开发表达。每条需求必须同时引用：详细需求目录中的原子行、发布需求清单中的处置、本文对应模块规则、追踪矩阵中的直接验收场景，以及批准后的 E1/决策记录。

## 3. 字段规格

每个对象字段必须登记以下属性，缺少实例值时使用 `[待确认]`，不得由开发自行选择：

| 属性 | 要求 |
| --- | --- |
| 字段标识与名称 | 标识稳定、中文名称业务化，历史版本可解释 |
| 业务定义 | 说明含义、使用场景和不适用条件 |
| 数据来源 | 人工、受控主数据、仪器、接口、计算或系统生成 |
| 类型与格式 | 字符、数字、日期时间、枚举、文件、签名等；单位和精度明确 |
| 必填规则 | 按状态、业务类型、方法、场所和条件适用性定义 |
| 唯一性 | 定义唯一范围、冲突处置和幂等键 |
| 版本规则 | 可覆盖、生成新版本、只读快照或不可变原始值 |
| 权限与密级 | 查看、创建、修改、审批、导出和脱敏范围 |
| 校验与异常 | 格式、范围、交叉字段、资源有效性和错误反馈 |
| 审计 | 是否记录旧值、新值、原因、时间、操作者和签名状态 |
| 保存与销毁 | 记录类别、保存期、冻结、归档和批准销毁规则 |

## 4. 流程与状态规格

每个状态转换固定登记：当前状态、操作、操作角色、前置条件、禁止条件、下一状态、失败状态、并发版本、审计事件、消息和可撤销性。

通用失败规则：

- 重复请求使用业务幂等键，不生成第二有效对象或重复流水。
- 并发修改使用受控版本校验；后提交者收到状态已变化，不覆盖先提交结果。
- 网络中断不得产生未知提交结果；恢复后可查询原请求状态并安全重试。
- 权限不足、资源失效、非法状态和数据缺失必须明确拒绝原因并记录高风险事件。
- 删除优先转换为作废、停用或被替代；物理删除仅限未形成业务事实且制度允许的对象。
- 更正保留旧值、原因、签名和影响对象；已发布报告/证书受影响时进入更正、撤回或召回流程。

## 5. 审计与电子签名

| 控制 | 开发要求 |
| --- | --- |
| 关键操作 | 新增、修改、作废、审批、签名、发布、导出、权限、配置、接口补偿和恢复均留痕 |
| 审计内容 | 对象、版本、操作、前后值、原因、身份、角色、时间、来源终端和关联请求 |
| 不可变性 | 普通业务角色不得修改或删除审计；特权访问单独审计 |
| 签名绑定 | 绑定签名人、目的、对象版本、内容摘要、可信时间和验签状态 |
| 签后变化 | 任何影响签名内容的变化必须使旧签名状态可识别，并触发重新签名/审批 |
| 失败处理 | 身份、证书、时间戳或验签失败时不得完成受控操作 |

具体签名节点、方式和时间参数仍受 `TBD-010` 阻塞。

## 6. 接口规格

每个接口在进入开发前必须完成：系统所有者、数据所有者、方向、触发事件、顺序、字段版本、认证授权、幂等键、超时、重试、对账、补偿、恢复、人工兜底、监控、审计和数据保存期。

接口失败不得静默覆盖受控记录；原始载荷、转换结果、失败原因、重试次数和最终处置必须可追溯。实际协议、地址和网络拓扑由后续技术基线定义。

## 7. 报表、消息与预警

- 报表指标必须登记名称、业务定义、分子、分母、排除项、时间范围、数据源、刷新时间、权限、责任人和可重算验收样例。
- 消息必须登记触发事件、收件角色、最小化内容、渠道、发送时限、确认、重试、升级和失败待办。
- 阻断类预警必须与业务状态门禁一致；仅关闭通知不得解除业务阻断。
- 所有导出包含条件、生成时间、责任信息和适用的水印/密级，并记录审计。

## 8. 验收规格

每条首期需求至少包含以下适用场景：正常、权限拒绝、非法状态、缺失数据、重复提交、并发修改、撤回/退回、作废/更正、接口失败、恢复和审计追踪。场景必须直接断言需求编号的验收表达。

开发准入审查按以下结果判定：

| 结果 | 条件 |
| --- | --- |
| 可开发 | 上游业务需求已批准，规格字段完整，依赖已关闭，直接 TC 存在 |
| 条件可开发 | 仅存在已书面接受且不改变业务语义的技术依赖 |
| 不可开发 | 业务规则、数据含义、权限、状态、接口主责或验收仍待确认 |

## 9. 原型校准

仅在 `BL-BIZ-1.0` 批准后执行。每个页面、字段、操作和状态必须引用批准需求；原型新增能力不得反向覆盖 SRS，而应形成需求变更申请。
